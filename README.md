# Learning Probability Flows with Neural Networks

Two Jupyter notebooks in which a neural network $v_\theta(t, x)$ learns a time-dependent velocity field
whose flow transports the standard Gaussian $\mathcal N(0, I)$ in $\mathbb R^2$ into a target distribution.
Samples are generated by integrating $\mathrm dx/\mathrm dt = v_\theta(t, x)$ with a hand-written
fixed-step 4th-order Runge–Kutta solver (RK4).

| part | notebook | method | target |
|---|---|---|---|
| 1 | [`01_flow_matching_2d/flow_matching_2d.ipynb`](01_flow_matching_2d/flow_matching_2d.ipynb) | Flow Matching (Lipman et al., 2023), conditional OT path, $\sigma_{\min} = 0$ | 8 Gaussians, checkerboard |
| 2 | [`02_rectified_flow_boltzmann/rectified_flow_boltzmann.ipynb`](02_rectified_flow_boltzmann/rectified_flow_boltzmann.ipynb) | Metropolis Monte Carlo + Rectified Flow (Liu et al., 2023), 1-RF and one reflow step | Boltzmann distribution of a 2-D double-well potential at $k_BT = 0.5,\ 1,\ 2$ |

**Part 2** covers:
- the theory of Markov chain Monte Carlo (Frenkel & Smit, §3.1–3.2);
- Metropolis sampling of $V(x_0, x_1) = \varepsilon\,[c\,(x_0^2 - 1)^2 + (x_0 - x_1)^2 + d\,(x_0 + x_1)]$ with $\varepsilon = 3,\ c = 1,\ d = 0.5$;
- Rectified Flow trained on the Monte Carlo samples, checked against the exact distribution and the exact velocity field;
- the quality of the samples and of the learned field versus temperature, number of training samples, number of RK4 steps and the placement of the time steps.

Each notebook is self-contained: all code is defined in its cells, next to the equations it implements.

## Repository layout

```
01_flow_matching_2d/
  flow_matching_2d.ipynb          the notebook (executed, with outputs)
  checkpoints/                    trained weights (2 networks)
02_rectified_flow_boltzmann/
  rectified_flow_boltzmann.ipynb  the notebook (executed, with outputs)
  checkpoints/                    trained weights (8 networks)
  data/                           Metropolis Monte Carlo training sets (k_B T = 0.5, 1, 2)
  results/                        stored samples and evaluation results
  figures/                        figures written by the notebook (PNG + PDF)
requirements.txt
```

## Running

```bash
python -m venv .venv && source .venv/bin/activate
pip install torch --index-url https://download.pytorch.org/whl/cpu    # or a CUDA build
pip install -r requirements.txt
jupyter lab
```

Open a notebook and run all cells from its own folder. Both notebooks use a GPU if one is available and
otherwise run on the CPU.

The trained weights, the Monte Carlo data and (for part 2) the expensive evaluation results are stored in
the repository, so the notebooks load them instead of recomputing: part 1 runs in a few minutes, part 2 in
about a minute on a laptop CPU. To recompute from scratch, delete `checkpoints/` (training: a few minutes
per network on a GPU, about ten on a CPU) or, for part 2, `results/` (evaluation: about three minutes on a
GPU, about an hour on a CPU).
